# Local Model ระยะถัดไป: ดึงสินค้าและสต๊อกก่อนตอบ

วันที่พัฒนาและทดสอบ: 18 พฤศจิกายน 2026

## สิ่งที่เปลี่ยน

เพิ่ม `src/lib/ai/catalogPrefetch.ts` เป็นส่วนค้นข้อมูลที่ไม่เรียก AI และต่อเข้าชุดทดสอบ local เท่านั้น ยังไม่ต่อฐานข้อมูลร้านจริงหรือเปลี่ยน production

ลำดับใหม่:

```text
ข้อความลูกค้า + สิทธิ์ร้านที่ระบบกำหนด
  → ระบบเรียก search_products / check_stock ที่ร้านมีสิทธิ์
  → บันทึกผลเป็นหลักฐานในเทิร์นปัจจุบัน
  → ส่งผลให้ local model ร่างคำตอบ
  → ผ่านวงจรตรวจ grounding เดิม
```

ระบบค้นให้ก่อน ไม่ต้องรอโมเดลตัดสินใจเรียกเครื่องมือเอง ผลนี้จึงไม่ใช่หลักฐานว่าโมเดลเรียนรู้ tool calling ได้ดีขึ้น

## การจำกัดขอบเขต

- เปิดด้วย `EVAL_CATALOG_PREFETCH=1` และต้องใช้ `read_only` เท่านั้น คำสั่ง `npm run eval:local` เปิดให้เป็นค่าเริ่มต้น
- เลือกเรียกเฉพาะ `search_products` และ `check_stock` ที่อยู่ในสิทธิ์ร้านเดิม ไม่รับชื่อเครื่องมือหรือรหัสร้านจากคำสั่งของลูกค้า
- ร้าน Q&A ที่ไม่มีสิทธิ์แคตตาล็อกไม่ถูกเพิ่มสิทธิ์
- ไม่มี cache ระหว่างคำขอ ผลครั้งถัดไปต้องเรียกอ่านใหม่
- ข้อความทักทายอย่างเดียวและข้อความว่างไม่ค้นข้อมูล สำหรับข้อความอื่นของร้านที่มีแคตตาล็อก ระยะนี้ค้นแบบอนุรักษนิยมโดยไม่ใช้ตัวจำแนก intent เพิ่ม จึงอาจค้นแม้ข้อความไม่เกี่ยวกับสินค้า
- คำถามดูสินค้าทั้งหมดใช้การค้นแบบรายการ จำกัด 5 รายการและไม่เรียก check_stock ด้วยชื่อว่าง
- คำถามระบุสินค้าไม่พบจะไม่ถูกเปลี่ยนเป็นการเลือกสินค้ารายการแรกแทน
- หากการค้นล้มเหลว ผลว่างผิดรูปแบบ หรือยาวเกินขอบเขต ให้การทดสอบล้มเหลวก่อนสร้างคำตอบ ไม่สลับไป cloud และไม่เปิดเผยข้อความผิดพลาดจากฐานข้อมูล
- เอาแคตตาล็อกคงที่ออกจากทั้ง prompt และ grounding evidence ในโหมดนี้ ราคาและสต๊อกต้องมาจากผลเครื่องมือในเทิร์นปัจจุบัน ไม่ได้ลบประวัติบทสนทนาเดิม
- แยก `systemToolCalls` และ `modelToolCalls` ในรายงาน JSON ส่วน `toolCalls` เป็นรายการเครื่องมือที่ทำงานจริงรวมทั้งสองแหล่ง เพื่อใช้ตรวจผลการทำงานของระบบ ไม่ใช่คะแนนความสามารถเลือกเครื่องมือของโมเดลล้วน ๆ

ส่วนค้นนี้ใช้ตัวทำงานที่ผู้เรียกส่งเข้ามา โดยส่งขอบเขต `shopId` แยกจากคำค้น ผู้ต่อกับฐานข้อมูลจริงยังต้องบังคับสิทธิ์และกรองร้านในทุก query เอง การทดสอบครั้งนี้ใช้ตัวทำงานในหน่วยความจำที่ผูกกับร้านจำลองทีละร้าน ไม่ใช่การพิสูจน์ RLS หรือฐานข้อมูล production

## ผลทดสอบโค้ด

เพิ่ม 12 กรณีทดสอบ ครอบคลุมลำดับการค้น สิทธิ์ร้าน การไม่ทำธุรกรรม การไม่ใช้ cache การแยกร้าน คำค้นสินค้าที่ไม่พบ การไม่เลือกสินค้ารายการแรกแทน การไม่ใช้แคตตาล็อกคงที่ และการหยุดก่อนเรียกโมเดลเมื่อข้อมูลผิดรูปแบบ

แก้ตัวค้นในร้านจำลองไม่ให้คำลงท้ายคำถามว่า “ไหม” ตรงกับ alias สินค้า “ไหม” โดยบังเอิญ ไม่ได้แก้ตัวค้นฐานข้อมูลจริงในขั้นนี้

**ผ่านเกณฑ์อัตโนมัติ 6/6 ไม่ได้แปลว่าคำตอบทุกประโยคถูกต้องหรือพร้อมขายจริง** เมื่อตรวจข้อความพบว่า product-05 มีคำจีนปนและข้อความสุขภาพที่ไม่มีในหลักฐานร้าน ส่วน prompt_injection-01 ยกตัวอย่างสินค้าบางชื่อที่ไม่อยู่ในผลค้น คะแนนเดิมยังตรวจไม่ครอบคลุมข้อผิดพลาดลักษณะนี้ ต้องเพิ่มตัวตรวจคำตอบก่อนเปิดใช้จริง

เวลาในตารางไม่ใช่ p95 ไม่รวมเวลาเชื่อมช่องทาง LINE/Messenger และไม่ใช่ผลทดสอบหลายร้านพร้อมกัน การผ่าน unknown-product และ cross-shop ในขั้นนี้เป็นผล unit/integration tests กับข้อมูลจำลอง ไม่ใช่การทดสอบโจมตี production

## วิธีทดสอบซ้ำ

```powershell
cd C:\Users\Jack\Documents\DealMee
$env:EVAL_CASE='product-01'
npm run eval:local
```

เปรียบเทียบกับโหมดก่อนค้นอัตโนมัติ:

```powershell
$env:EVAL_CATALOG_PREFETCH='0'
npm run eval:local
```

เปิดกลับด้วย `$env:EVAL_CATALOG_PREFETCH='1'` ค่า env ค้างอยู่ในหน้าต่าง PowerShell เดิม อย่ารวมผลสองโหมดเป็นผลทดลองเดียวกัน รายงาน JSON ระบุ `catalogPrefetch` เพื่อแยกผลแต่ละโหมด

รายงานปกติอยู่ใน `eval-reports` หรือโฟลเดอร์ที่กำหนดด้วย `EVAL_OUT` รายงานจริงของรอบนี้บันทึกอยู่ในโฟลเดอร์ `local-eval-prefetch` ของงานในแชตนี้

## งานที่ต้องทำก่อนร้านจริง

1. เพิ่มการตรวจข้อความนอกหลักฐานและภาษาให้ครอบคลุมกว่าตัว scorer เดิม โดยไม่ถือว่าการมี citation ทำให้ทุกคำกล่าวอ้างถูกต้อง
2. ต่อ repository สำหรับการค้นจริงที่อ่านข้อมูลอย่างเดียว ตรวจการแปลงภาษาลูกค้าเป็นคำค้น และบังคับ tenant scope ในฐานข้อมูล คำถามเต็มประโยคที่ร้านจำลองจับจาก alias ได้ อาจไม่ตรงกับพฤติกรรม query ฐานข้อมูลจริง
3. เพิ่ม schema validation ครบถ้วนสำหรับเครื่องมือที่โมเดลเรียกเอง รวมถึงการจัดการข้อมูลไม่พบ การถามต่อแบบอ้างข้อความก่อนหน้า และการส่งต่อคน
4. วัด prompt budget โดยรวมประวัติและผลค้น ไม่ปล่อยให้คำสั่งระบบถูกตัดเงียบ ๆ
5. ทดสอบโหลดพร้อมกันและต้นทุนจริง ก่อนตัดสินใจซื้อเครื่องหรือเช่า VPS

สถานะ: **ระบบค้นข้อมูลก่อนตอบทำงานใน sandbox แล้ว ยังไม่เปิด production ไม่สร้างออเดอร์จริง และยังไม่รับรองว่า DealMee ทั้งระบบเป็น local-only**
