# รีวิวสกิลรายคืน

คืนละครั้ง ระบบดูสัญญาณการเรียนรู้ของแต่ละร้าน แล้วเสนอสกิลฉบับร่างให้เจ้าของร้านกดรับหรือไม่รับเอง
บอทจะไม่เปิดใช้สกิลให้ และจะไม่ถือว่าข้อความในร่างเป็นข้อเท็จจริงจนกว่าร้านจะยืนยัน

งานนี้คนละตัวกับตัวตั้งเวลา 5 นาทีใน [scheduler-pg-cron.md](./scheduler-pg-cron.md)

## สิ่งที่ร้านเห็น

- แดชบอร์ด: แถบ «ข้อเสนอจากการรีวิวเมื่อคืน» เมื่อมีร่างค้างอยู่ พาไปหน้าทักษะ
- หน้าทักษะ (`/dashboard/skills`): การ์ดสรุปภาษาไทย เหตุผลที่เสนอ (คำถามที่ตอบไม่ได้ / แอดมินตอบเอง / กดไม่ชอบ) ปุ่ม **รับไว้เป็นฉบับร่าง** และ **ไม่ใช้ข้อเสนอนี้**
- รับไว้ = สกิลยังเป็น candidate ต้องกดเปิดใช้เอง และต้องยืนยันข้อเท็จจริงถ้าจะให้บอทใช้อ้างอิง
- ไม่ใช้ = เก็บร่างนั้น และจะไม่เสนอเรื่องเดิมซ้ำ
- ถ้ายังไม่มีคำตอบจากร้าน การ์ดจะบอกให้เติมข้อเท็จจริง ระบบไม่แต่งราคาหรือนโยบายให้

ถ้าร้านไม่มีสัญญาณในรอบนั้น จะไม่มีการเรียกโมเดล และไม่มีการ์ดเปล่า

## สัญญาณที่ใช้

ย้อนหลังไม่เกิน 7 วัน และยังไม่เคยถูกรีวิว:

| สัญญาณ | ที่มา |
|---|---|
| คำถามที่ตอบไม่ได้ | `knowledge_gaps` ที่ยังเปิดอยู่ |
| กดไม่ชอบ | `chat_message_feedback` ที่ `rating = down` คำตอบที่ร้านแก้ (`corrected_response`) ใช้เป็นข้อเท็จจริงได้ |
| แอดมินตอบเอง | `chat_messages` ที่ `sender_type` เป็น `agent` / `human` / `admin` ไม่นับบรอดแคสต์ |

ข้อความของบอทไม่ถูกส่งเข้าโมเดล และไม่ถูกคัดลอกเป็นข้อเท็จจริง
ข้อเท็จจริงในร่างคัดลอกจากข้อความแอดมินหรือข้อความที่ร้านแก้เท่านั้น แล้วผ่าน `redactPii` ก่อน
คำถามที่ไม่มีคำตอบจากร้านได้ร่างที่ช่องข้อมูลว่าง และคำแนะนำให้ร้านเติมเอง

ร่างที่สร้างจะเป็น `shop_skills.status = candidate`, `facts_confirmed = false` แล้วเข้าคิวทดสอบเงาแบบ #103
ร้าน BYOK ใช้คีย์ Gemini ของร้านเท่านั้น ถ้าไม่มีคีย์ Gemini ร้านนั้นถูกข้าม

## ตั้งเวลา

`vercel.json` เรียก `GET /api/cron/skill-review` เวลา `0 18 * * *` (01:00 น. เวลาไทย)
Vercel ส่งเฮดเดอร์ `Authorization: Bearer <CRON_SECRET>` ให้เองเมื่อตั้ง `CRON_SECRET` ไว้ในโปรเจกต์

แต่ละรอบทำทีละชุด ภายในเวลาของ serverless แล้วเรียกรอบถัดไปเองจนกว่าร้านที่ยังไม่รีวิวในวันนั้นจะหมด
ถ้ารันซ้ำในวันเดียวกัน (ตามปฏิทินไทย) ร้านที่จบไปแล้วจะไม่ถูกเรียกโมเดลซ้ำ

## ตัวแปรสภาพแวดล้อม

| ตัวแปร | จำเป็น | ความหมาย |
|---|---|---|
| `CRON_SECRET` | ใช่ | ตัวลับเดียวกับ cron เดิม ถ้าไม่ตั้ง เส้นทางนี้ตอบ 503 |
| `SKILL_REVIEW_ENABLED` | ไม่ | ตั้งเป็น `0` เพื่อให้เส้นทางตอบสำเร็จแต่ไม่รีวิว |

คีย์ Gemini ไม่ได้อยู่ใน env ของงานนี้
ร้านทั่วไปใช้คีย์ที่ Super Admin บันทึกไว้ (`GEMINI_API_KEY` / `GEMINI_MODEL`)
ร้านแผน BYOK ใช้คีย์ใน `shop_ai_keys` และต้องเป็นผู้ให้บริการ Gemini

## เรียกเองตอนตรวจ

```bash
curl -sS -X POST \
  -H "Authorization: Bearer $CRON_SECRET" \
  https://app.dealmee.app/api/cron/skill-review
```

ตอบ 401 = ค่า `CRON_SECRET` ไม่ตรง, 503 = ยังไม่ได้ตั้งค่า
