# เดโมบนหน้าแรก (ลองคุยกับบอทเลย ไม่ต้องสมัคร)

หัวข้อ `#try` บนหน้าแรก ให้ผู้เข้าชมพิมพ์คุยกับบอทจริงใน **ร้านตัวอย่าง 3 ร้าน** โดยไม่ต้องมีบัญชี

| ร้าน | id | โชว์อะไร |
|---|---|---|
| Sunday Clothing (ร้านค้าออนไลน์) | `d3300000-…-000000000001` | ค้นสินค้า · การ์ดสินค้า · สั่งซื้อ · QR |
| Moonlight Spa (จองคิว) | `d3300000-…-000000000002` | บริการ · คิวว่าง · จอง/เลื่อน/ยกเลิก |
| CleanMate (ธุรกิจบริการ) | `d3300000-…-000000000003` | ตอบจากคลังความรู้ · ส่งต่อแอดมิน |

## ทำงานยังไง
- หน้าเว็บ → `POST /api/demo/chat` → engine ตัวเดียวกับ LINE webhook (`startSalesAgentPlanning`, `isPlayground: true`)
- ผู้เข้าชมจำด้วย cookie `dm_demo` (httpOnly) แชทเก็บเป็น `conversations.platform = 'DEMO'`
- **ไม่มีอะไรออกนอกระบบ:** ร้านเดโมไม่มี LINE token, ปิดแจ้งเตือนแอดมิน, route ลบ token ทิ้งอีกชั้นก่อนเรียก engine
- **QR ไม่โชว์ของจริง:** เลขพร้อมเพย์ของร้านเดโมคือ `0000000000` (ไม่มีเจ้าของ) และ route ตัดรูป QR ทิ้ง ส่งเป็นภาพตัวอย่างแทน
- **ตรวจสลิปไม่เปิด** (เปลืองเครดิต EasySlip และต้องใช้สลิปจริง)

## เพดานค่าใช้จ่าย (`src/lib/demo/shops.ts`)
| | ค่า |
|---|---|
| ต่อผู้เข้าชม (cookie) ต่อวัน | 12 ข้อความ |
| ต่อเครือข่าย (IP) ต่อวัน | 40 ข้อความ — กันคนล้าง cookie วนยิง |
| ทั้งระบบต่อวัน | 600 ข้อความ |
| ความยาวต่อข้อความ | 300 ตัวอักษร |

นับในฐานข้อมูล (`claim_demo_message`) เพราะ Vercel แต่ละ instance ไม่แชร์หน่วยความจำกัน
เกินเพดานแล้วหน้าเว็บบอกให้สมัครทดลองใช้ฟรีแทน — ไม่มีการเรียก AI

## ล้างข้อมูล
cron (`/api/cron/follow-up` ทุก 5 นาที) เรียก `cleanup_demo_shops(6)` — ลบแชท ออเดอร์ การจอง lead ของร้านเดโมที่ไม่มีใครแตะเกิน 6 ชั่วโมง และคืนสต็อกเป็น 50
ไฟล์ QR ที่ถูกสร้างใน storage bucket `qr-codes/<id ร้านเดโม>/` ยังไม่ได้ลบอัตโนมัติ (ไฟล์เล็ก ลบมือได้ถ้าเยอะ)

## ติดตั้ง
วางไฟล์ `supabase/migrations/20261101000000_live_demo.sql` ทั้งไฟล์ใน SQL Editor แล้ว Run (รันซ้ำได้)
ถ้ายังไม่รัน หน้าเว็บจะขึ้น "เดโมขัดข้องชั่วคราว" และ log มี `sample shop missing`

## เช็คการใช้งาน
```sql
-- วันนี้ใช้ไปเท่าไหร่
select sum(messages) from demo_usage
where day = (now() at time zone 'Asia/Bangkok')::date and visitor_id like 'v:%';

-- คนลองถามอะไรกันบ้าง (ไว้ปรับข้อมูลร้านตัวอย่าง)
select c.shop_id, m.message, m.created_at
from chat_messages m join conversations c on c.id = m.conversation_id
where c.platform = 'DEMO' and m.sender_type = 'user'
order by m.created_at desc limit 50;
```

## แก้ข้อมูลร้านตัวอย่าง
แก้ใน migration แล้วรันซ้ำ (สินค้า/บริการ/คลังความรู้ใช้ `on conflict do nothing` — ถ้าจะแก้แถวเดิมให้ update ตรง ๆ หรือลบแล้วรันใหม่)
หรือแก้ใน `src/lib/demo/shops.ts` สำหรับคำถามตัวอย่างและข้อความทักทายบนหน้าเว็บ — ข้อความทักทายในไฟล์นั้นต้องตรงกับ `greeting_message` ใน migration
